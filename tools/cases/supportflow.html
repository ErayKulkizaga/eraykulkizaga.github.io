02 / The boundary that matters

The change and its history
belong together.

Business services own the transaction. Repositories add records without committing independently, so a failed write cannot leave a successful-looking audit trail behind.

Every lookup has a tenant.

Organization membership is verified before access. Cross-tenant document identifiers resolve to the same missing-record response.

History is append-only.

PostgreSQL rejects ordinary updates, deletes and truncation on the audit table. Audit records omit credentials and raw message bodies.

03 / A document becomes background work

Follow the document.
Keep the evidence.

PDF, TXT and Markdown files move through explicit states. Upload, extraction, failures and retries remain inspectable.

  1. 01 / Receive

    Bound and validate

    Stream a size-limited upload. Check its content and generate a tenant/document/version object key.

  2. 02 / Persist

    Commit the version

    Store the document version and upload audit event atomically before queue publication.

  3. 03 / Process

    Scan and extract

    Celery workers scan and extract the version. Terminal state and its audit event share a transaction.

  4. 04 / Recover

    Make retries explicit

    Retry-safe workers preserve the version contract. Broker failures leave an inspectable failure state.

Design tradeoff / ADR 0005

A crash window remains between database commit and queue publication. The repository records an outbox or reconciler as a future reliability decision.
